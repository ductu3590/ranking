## Locked contract

- `SetupDraftV2` includes draft version, identity, revision, idempotency, four-step state, participant/member/athlete snapshots, stable pairs, format config, draw/stage plans, readiness, invalidation, and timestamps.
- State machine is `local_only -> server_draft -> roster_ready -> pairing_ready -> draw_drafted -> finalized`; participant/format/pair/draw changes invalidate only the affected downstream work.
- Load/save use complete aggregate responses and revision CAS. Idempotent retries return the stored response; changed payload under the same key is rejected.
- Readiness is calculated from real data. Blocker/warning codes are listed in the contract, including odd doubles, stale draw, tenant mismatch, missing athlete identity, result lock, imbalance, and pending playoff slots.
- Legacy draft redirects to the four-step workspace; finalized records redirect to schedule/operations. Finalize does not transition to LIVE.
- `group_knockout` has two stages in one division and explicit source-stage -> target-stage progression. The only builder is `buildDivisionStagePayloads()`.
- Pair IDs are stable, member selection uses `member_id`, server resolution stores `athlete_id`, and `locked` pairs survive unrelated changes and regeneration.
- Knockout waiting sides use progression placeholders shared by preview, persistence, and bracket; no fake entrant is inserted.
