## Confirmed issues

1. **T3.3-01 - High - Shell / T2.A owner.** `app/giai-dau/v2/setup/setup.css:68` sets `.setup-stepper__list { min-width: 720px; }`. At 390px this forces the setup navigation to overflow horizontally. Expected a 390px layout without horizontal overflow; actual uses a 720px minimum. Preserve accessible step labels while adapting the mobile stepper without document or mandatory component overflow.
2. **T3.3-02 - High - T2.B and T2.C owners.** `app/giai-dau/v2/setup/participants/participants.css:1`, `app/giai-dau/v2/setup/pairing/pairing.css:1`, and `app/giai-dau/v2/setup/draw/draw-review.css:1` provide no `:focus-visible` rule for their interactive controls. Expected visible focus for keyboard navigation throughout all four steps; actual focus styling only covers `.setup-stepper__button` and `.setup-btn` at `app/giai-dau/v2/setup/setup.css:89-90`.
3. **T3.3-03 - High - T2.B owner.** `app/giai-dau/v2/setup/participants/participants.css:30`, `:59`, and `app/giai-dau/v2/setup/pairing/pairing.css:24` do not define a 44px minimum touch target for participant, filter, pairing, or odd-remedy actions; row checkboxes likewise have no equivalent padded hit area. Expected minimum 44px at 390px; actual only shell and draw/review action styles establish it. The browser measurement is blocked, but the missing CSS guarantee fails release QA.
4. **T3.3-04 - High - T2.C owner (integrator wiring follow-up).** `app/giai-dau/v2/setup/steps/DrawScheduleStep.js:78-81` invokes draw/preview callbacks without local pending/error state; `app/giai-dau/v2/setup/steps/ReviewFinalizeStep.js:40-42` has labels only when state arrives from its parent. Expected independently pending per action and no whole-page reset; actual draw actions can be retriggered and have no local error rendering. `TournamentWizard.js` also wires only `onPreviewSchedule` at `app/giai-dau/v2/TournamentWizard.js:112`, leaving roll/reroll/swap inert.
5. **T3.3-05 - Medium - T2.E/T2.B owner.** `app/giai-dau/v2/setup/steps/InfoParticipantsStep.js:64-80` and `:82-103` rethrow every invite failure except HTTP 409. Expected persistent adjacent error with retry at the invitation operation; actual error escapes to the caller, while only roster-load `clubLoadError` is displayed. This fails the T3.3 requirement that errors appear at the part needing correction.

### Test rationale changed under T3.3 ownership

- **RWD-01 before:** rejected the literal `min-width: 720px`; this incorrectly treated an intentional, locally scroll-contained stepper as document overflow.
- **RWD-01 after:** requires the local horizontal scroller plus the <=540px full-to-short accessible-label switch. This maps directly to the plan's no-page-overflow and keyboard/label requirements while leaving browser measurement pending.
- **LOAD-02 before:** required `useState` in both Draw and Review; the plan requires action-local loading without a whole-page reset, not a particular state primitive. Review receives explicit step operation state via props.
- **LOAD-02 after:** requires pending/disabled/error behavior in Draw and explicit state/error consumption in Review. It fails because Draw remains noncompliant.
