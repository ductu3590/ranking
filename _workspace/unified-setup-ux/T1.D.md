# T1.D — Browser harness and fixtures

## Scope

- Added only `tests/unified-setup-v2/browser/**` and this handoff.
- Production code, `package.json`, shared tests, and frozen files were not changed.

## Fixtures

`fixtures.js` defines tenant-scoped fixture metadata for:

- 14 athletes: 7 pairs, groups A/B sized 4/3, 9 group matches, 12 total matches without third place or 13 with it.
- 15 athletes: 7 complete pairs plus one unpaired member; finalize must be blocked and the UI must expose add-member, reserve-member, or switch-format choices.

The fixture records use `memberId`/`athleteId` separately and accept the provisioned `groupId`; no production tenant is hard-coded.

## Browser coverage

`setup.browser.test.js` drives the real setup URL at 390px, tablet (768px), and desktop (1440px), using the provisioned admin `group_session` and group-scoped `PICKHUB_QA_GROUP_ID`.

If required environment is absent, the test exits successfully with an explicit `SKIP` reason naming the missing variables. This is development-only; release gate must provision and run the harness rather than treat the skip as release evidence.

Required environment: `PICKHUB_QA_BASE_URL`, `PICKHUB_QA_ADMIN_SESSION`, `PICKHUB_QA_GROUP_ID`, and `CHROME_EXECUTABLE` (or Playwright-managed Chromium).

## Cleanup

Use the existing safe harness cleanup only with the explicitly provisioned group IDs:

`node scripts/qa/cleanup-browser-harness.js <group_id>`

It deletes only listed tenant records in dependency order, refuses cross-tenant links, never uses `DROP`/`TRUNCATE`, and verifies the supplied IDs. Do not delete by name or prefix. Provision with `scripts/qa/provision-browser-harness.js` into an env file outside the repository.
