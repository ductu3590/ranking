## UI / API shape
- `InfoParticipantsStep` receives `draft`, `roster`, `onDraftChange`, `onSaveDraft`, `loading`, `error` from the T2.A/T2.D shell and only emits draft-shaped participant changes.
- `ParticipantRosterPicker` renders search, active/inactive/all filters, member_id keyed checkboxes, highlighted `Chọn toàn bộ thành viên đang hoạt động`, separate visible-result select/unselect, `Đã chọn X/Y`, hidden-selection retention notice, inactive badge/warning, and duplicate-name metadata (`member_id`, member code, athlete id, club name).
- `FormatPairingStep` receives `draft`, `roster`, `onDraftChange`, builds/updates `pairs`, `unpairedMemberIds`, `reserveMemberIds`, and `pairingDraft` without calling API or Supabase directly.
- `PairingBoard` uses `lib/tournament/pairingDraft.js` for add/remove/lock/regenerate behavior, surfaces `UNPAIRED_MEMBER`, supports manual/automatic preview/apply labels, explicit lock/unlock, explicit swap, and the three odd-count choices.
- Mobile behavior uses buttons and checkboxes only; no drag-and-drop dependency.
